### D の決定による設計上の帰結

- ブラウザに配るのは**加工済みグラフのみ**（数十KB）。時刻表 bin は配らない。
- ただし **ビルド時には ODPT の `odpt:TrainTimetable` を使う**。用途は2つ:
  1. 駅間所要時間 = 隣接停車間隔の中央値
  2. 乗換待ち時間 = 路線・時間帯ごとの運行間隔から算出（v1 の「一律5分」を精緻化）
- `src/routing/raptor.ts` は作らない。ただしネットワークのスキーマは
  後から時刻表を足せる形（駅・路線・エッジを分離した正規化形）にしておく。

## 2. データ更新：調査結果（重要）

### 使えるもの

**公共交通オープンデータセンター (ODPT)** が本命。無料登録でアクセストークン発行。

- エンドポイント: `https://api.odpt.org/api/v4/`（要 `acl:consumerKey`）
- 一部は `https://api-public.odpt.org/api/v4/` でキー不要（**都営のみ**）
- 検証済み: `odpt:Station` に `geo:lat` / `geo:long` が入っている
  → **parosky.net のリンク切れ問題は解決**（座標を別途調達する必要がない）
- 検証済み: `odpt:TrainTimetable` に列車ごとの各駅発着時刻（分単位）がある
  → **駅間所要時間を実時刻表から自動算出できる**（手作業CSVが不要になる）
  → 都営の列車時刻表は 5,600 本、`dc:date` は **2025-12-15**（現行ダイヤ）
- 検証済み: `odpt:PassengerSurvey` に年次の乗降人員がある
  → **手書きの「優先度」列を実データで置き換えられる**

### ライセンスの切り分け（設計を左右する）

| ライセンス | 事業者 | 期限 |
|---|---|---|
| **CC BY 4.0** | 東京都交通局（都営地下鉄・都電・日暮里舎人） | なし |
| **公共交通オープンデータ基本ライセンス** | **東京メトロ**、東京臨海高速鉄道（りんかい線）、つくばエクスプレス、多摩都市モノレール、ゆりかもめ | なし |
| **チャレンジ限定ライセンス** | **JR東日本**、東急、東武、西武、京王、京急、小田急、相鉄 | **2027-03-14 に失効** |

チャレンジ限定ライセンスの実際の条文（第4条・第13条）を確認した:

- チャレンジへの**応募が必須**。応募以外の目的と判断されれば利用停止・法的措置の対象
- **2027年3月14日に許諾終了**、終了時は**データを削除する義務**

→ **JR東日本のデータを恒久公開アプリに使うのは不可**。ここが最大の制約。

基本ライセンス側の条文も設計に効く:

- 第4条2項(3) 「成果物以外の場所にデータの全部または一部を表示しない」
  → **生の時刻表JSONをリポジトリにコミットするのは避ける**。ビルド時に取得し、
    アプリが使う**加工済みデータ**（駅間所要時間など）だけを成果物として置く
- 第4条2項(4) 「データが更新されたら成果物を速やかに更新する」
  → **定期自動更新を仕組みとして持つべき**（GitHub Actions の cron）
- クレジット表示が必要（都営は「東京都交通局・公共交通オープンデータ協議会」）

### JR をどうするか（→ 要決定 A）

1. **現行の手動CSV方式を維持**（山手線・中央総武線のみ、公開時刻表から人力更新）
   座標は国土数値情報 N02（政府標準利用規約、最新は令和7年度版）で補完。
   *推奨。* 約60駅で、駅間所要時間はほぼ変わらないため保守コストは低い。
2. チャレンジに登録して JR を入れる（2027-03-14 以降に落とす前提のコードにする）
3. JR を落としてメトロ＋都営のみにする（山手線が消えるとコンセプトの説得力が落ちる）

### 路線範囲の拡張（→ 要決定 B）

基本ライセンス組はタダで足せる: りんかい線・つくばエクスプレス・ゆりかもめ・多摩都市モノレール。
りんかい線と TX は都心接続が良く、「30分圏」の絵が実際に変わる。

## 4. 機能改良

### 4.1 経路計算：静的グラフ + Dijkstra（モードA のみ）

v1 と同じ「静的グラフの最短路」だが、重みの質を上げる。

**エッジ重み（駅間所要時間）**
ODPT `odpt:TrainTimetable` の各列車について隣接停車駅の発着差を取り、その**中央値**を採用。
手作業CSVからの脱却がここで効く。要検討点:
- 列車種別（急行・快速・区間運転）の扱い。v1 は各駅停車のみを採用していた。
  まずは**各駅停車の中央値**を基本とし、種別違いは中央値に吸収させる方針で始め、
  外れ値（大江戸線の環状運転、支線直通など）はテストで検出して個別対応する。
- 直通運転（例: 副都心線⇔有楽町線、都営新宿線⇔京王）で線内に現れる駅の重複を正規化。

**乗換コスト**（v1 は一律5分）
- 同一駅内の路線間乗換 = 歩行時間 + 待ち時間。
  待ち時間は当該路線の**運行間隔から算出**（時刻表から日中帯の平均間隔を出し、その1/2）。
- 異名駅の徒歩乗換 = 既存 `walk.csv` を継承。距離が取れるものは座標から算出（80m/分）し、
  手動値があればそちらを優先。
- 結果として「昼間の副都心線で1本待つ」と「大江戸線で1本待つ」の差が出るようになる。

**アルゴリズム**
バイナリヒープ付き Dijkstra に置き換え（v1 は `for..in` 全走査の O(V²)）。
駅数が増えても中心駅切替が即応する。

**将来の拡張余地**
時刻表ベースの時刻依存探索（RAPTOR）は v2 では**作らない**が、
ネットワークのスキーマは駅・路線・エッジを正規化した形にしておき、
後から `timetable.bin` を足せば載せられる状態にする。

### 4.2 ラベル配置（v1 の一番の弱点）

現行: 手書き優先度で並べ、重なったら**消す**（新宿周辺で情報が大量に落ちる）。

改善:
- 優先度を **`odpt:PassengerSurvey` の乗降人員**で自動決定（手書き列を廃止）
- ズームレベル連動 LOD（引くと主要駅のみ、寄ると全駅）
- 消す代わりに **リーダー線付きで少しずらす**（半径は保持し角度方向に逃がす。
  半径＝所要時間という不変条件を壊さない逃がし方にする）
- 未表示駅も点は必ず描き、hover/tap でツールチップ表示

### 4.3 UI/UX

- **モバイル対応**（Pointer Events で pinch-zoom・pan、レスポンシブ、safe-area）
  → 「スマホ未対応」の解消
- **駅名インクリメンタルサーチ**（ダブルクリックで探す必要をなくす）
- **URL に状態を持たせる**（`?center=shinjuku&zoom=...`）→ 共有可能
- **統計パネル**：中心駅から30分で到達できる駅数 / 到達駅の所要時間中央値 /
  最遠駅。「30分説」への定量的な答えをその場に出す
- ~~比較モード~~ → **v2.1 に延期**（決定E）
- ダークモード、キーボード操作、`prefers-reduced-motion` 尊重
- 英語表示（ODPT に `en` タイトルがあるのでほぼ無料で付く）
- PNG / SVG エクスポート（README のスクショ更新が楽になる）

### 4.4 誠実さの担保（コンセプト7の維持）

- 「中心駅以外の駅間距離は無意味」を UI 上に常設表示
- 出典・ダイヤ基準日（`dc:date`）・ライセンス表記をフッタに自動生成
- モード A/B の違いと前提（乗換時間の仮定など）を読める場所に置く

## 5. テスト・自動デバッグ環境

### Vitest（ユニット）
- `dijkstra`：小さな手作りグラフで既知の最短路と一致
- 実データ回帰：主要区間（例 新宿→東京、渋谷→上野）の所要時間をスナップショット化し、
  公式の公開所要時間と突き合わせて桁違いを検出
- 駅間所要時間の妥当性：全エッジが 1〜10分の範囲に入る、負値・欠損がない、
  連結性（全駅が中心駅から到達可能）
- パイプライン：ODPT レスポンスのフィクスチャ → 期待する network.json

### Playwright（E2E + 視覚回帰）
- 中心駅を切り替えると駅位置が更新される
- 30分円上の駅の所要時間が 30±ε に収まる（DOM から検証）
- モバイルビューポートで pinch-zoom / pan が効く
- スクリーンショット比較でレイアウト崩れを検出（`toHaveScreenshot`）

### CI
- `ci.yml`：型チェック・lint・unit・e2e・build
- `data-refresh.yml`：月次で ODPT 再取得 → 差分があれば PR 自動作成
- `pages.yml`：master push で GitHub Pages にデプロイ

いずれにせよ v1 は git 履歴に残るので、案1でも失われるものはない。

## 8. ユーザーにお願いする準備作業

### (1) ODPT アカウント登録（必須・無料）

1. https://developer.odpt.org/ で登録（無料）
2. アクセストークン（consumer key）を発行
3. リポジトリ直下に `.env` を作り `ODPT_API_KEY=<発行したキー>`（`.gitignore` に追加する）
4. GitHub Actions 用に、リポジトリの Secrets に同じ値を `ODPT_API_KEY` として登録

※ 都営のみ `api-public.odpt.org` でキー不要。**東京メトロにはキーが必要**。
※ キーは私（Claude）が代行取得できないため、ここだけお願いします。

### (2) Playwright（ブラウザ自動デバッグ）

この WSL2 環境で chromium が起動することは**確認済み**（システムライブラリは足りている）。
必要なのはパッケージとブラウザ実体の追加だけ:

```bash
cd ~/dev/tokyo-train-time-map
npm i -D @playwright/test
npx playwright install chromium
```

`~/.cache/ms-playwright` には chromium-1228 が既にあるが、`@playwright/test` の
バージョンに対応するビルドが別途必要なため `install chromium` を実行する（約170MB）。
万一起動に失敗したら `sudo npx playwright install-deps chromium`。

### (3) Playwright MCP（任意・推奨）

入れておくと、私が開発中にブラウザを直接操作して見た目を確認・修正できる
（スクショ、クリック、コンソールエラー取得）。現在 MCP サーバーは未設定。

```bash
claude mcp add playwright -- npx -y @playwright/mcp@latest
```

追加後、`/mcp` で接続を確認してください。

## 10. レビュー（2026-07-25 実装分）

ODPT の登録に数日かかるため、**ODPT を使わずに v2 を先に完成させた**。
データは既存の手動 CSV を最小限だけ更新し、後から ODPT で置き換えられる形にしてある。

### やったこと

**データ（最小限の更新）**
- `make_dataset/` → `data/` に移動。CSV が唯一の入力になった
- **駅の緯度経度をリポジトリ内に取り込んだ** (`data/station_locations.csv`, 248駅)。
  旧 `download.sh` が参照していた parosky.net はリンク切れなので、コミット済みの
  `dist/map_data.js` から復元した。これで外部依存なしにビルドが通る
- 2017年7月以降に開業した2駅を追加し、路線内の駅番号を振り直した
  - 日比谷線 虎ノ門ヒルズ (H06)、山手線 高輪ゲートウェイ (YT06)
  - 所要時間は現行ダイヤの時刻表を実地で照合して決めた
    （神谷町→虎ノ門ヒルズ 1分 / →霞ケ関 2分、田町→高輪GW 2分 / →品川 2分）
  - 座標は Wikipedia
- `walk.csv` に 虎ノ門ヒルズ↔虎ノ門、高輪ゲートウェイ↔泉岳寺 を追加
- 248駅 / 358ノード / 551エッジ

**アプリ（全面的に書き直し）**
- webpack1 + jQuery + Snap.svg → **Vite 7 + TypeScript strict + Preact**。
  実行時依存は Preact のみ。**バンドルは 573KB → gzip後 13KB**
- ダイクストラ法を O(V²) の線形走査から**二分ヒープ版**に
- **経度の縮み (cos 緯度) を補正**。旧版は東京の緯度で方位が最大6度ほど歪んでいた
- ラベルの重なりを「消す」から**「接線方向にずらして引き出し線を引く」**に。
  半径＝所要時間は保つ。東京駅中心で 248駅中 217駅のラベルが出る
- **スマホ対応**（Pointer Events でピンチズーム・パン、レスポンシブ、60vh の地図領域）
- 駅名インクリメンタルサーチ、URL 状態同期、ダークモード、全体表示ボタン
- **統計パネル**：「東京駅から30分以内に218駅（88%）」のように元の問いに数字で答える
- 目盛の円は最遠駅までしか描かない。目盛ラベルは上下左右4か所に置いて常に見えるように

**テスト**
- Vitest 33件（ダイクストラ、極座標配置、ラベル配置、生成データの不変条件）
- Playwright 16件（desktop / mobile 両方。所要時間が画面距離に比例することを DOM から検証）
- CI（typecheck / lint / unit / e2e / build）と GitHub Pages デプロイのワークフロー

### 実装中に見つけて直したバグ

- `setPointerCapture` を取ると `pointerup` の `target` が SVG 自身に付け替わるため、
  **駅をクリックしても中心が切り替わらなかった**。押した時点の駅を覚えておく方式に変更。
  E2E テストで検出

### 判明したこと・積み残し

- 初版の所要時間は現行ダイヤと**1分程度ずれている箇所がある**
  （例: 日比谷線 六本木→神谷町 は初版4分、現在3分）。
  今回は「最小限の変更」方針のため他区間は触っていない。ODPT 移行でまとめて直す
- 比較モード（2駅の30分圏の重ね合わせ）は未実装（決定E のとおり v2.1）

`src/data/schema.ts` の `NetworkData` は変えなくてよい。手順は §7 フェーズ1 を参照。
